## 1. Підсумок

- **Загальний стан добрий.** Збірки, типи, лінти й тести зелені (див. §7). Ні Android, ні бекенд не мають P0 (втрати даних чи падінь).
- **Сучасність коду: 8/10 для Android, 7/10 для PWA.** Платформні рішення сучасні; відставання переважно у версіях бібліотек і кількох локальних звичках, а не в підході.
- **Топ-5 проблем:**
  1. **BE-01 (P1, безпека):** щогодинна розсилка пушів довіряє запису «я учасник спільного профілю» без перевірки членства. Знаючи uid і id профілю жертви, можна отримувати її пуші з назвами категорій і сумами. Підтверджено читанням коду і тестом на фейковій базі.
  2. **PWA-01 + PWA-02 (P1, безпека):** коренева адреса `maxtr-c238f.web.app/` віддається без CSP (перевірено curl), а частина значень із Firestore (колір і id тегів, id профілів тощо) вставляється в HTML без екранування. Учасник спільного профілю може підкласти скрипт власнику.
  3. **PWA-03 + PWA-04 (P1, жорстке правило «PWA не псує дані Android»):** увімкнення пушів на ноутбуці перезаписує FCM-токен Android, а вимкнення видаляє його. Редагування операції в PWA переписує документ цілком зі старої копії й може стерти поля, додані Android (наприклад, `monobankId`).
  4. **UX-01 (P1, доступність):** операцію і платіж боргу можна видалити лише свайпом. Немає дії для TalkBack і кнопки «Видалити» у формі редагування (перевірено grep).
  5. **UX-02 (P1, продукт):** бюджети не показують «витрачено X з Y». Текст порожнього стану обіцяє попередження «коли наближаєшся», а код попереджає лише про перевищення.

## 2. Міф чи правда: «ШІ пише застарілий код»?

**Для цього репо здебільшого міф.** Перевірено за офіційною документацією станом на листопад 2026, а не з пам'яті моделі.

**Сучасне (з доказами):**
- **Android SDK:** targetSdk і compileSdk 37, а Play вимагає 36. Нативні бібліотеки вирівняні під 16 КБ сторінки. AGP 9 з вбудованим Kotlin, KSP замість kapt, каталог версій.
- **Свіжі версії бібліотек:** Compose BOM 2026.09, Room 2.8.5, Lifecycle 2.11, Credential Manager 1.6 (вхід через Google без застарілого GoogleSignIn).
- **Платформні вимоги Android:** edge-to-edge, жест «назад» без `onBackPressed`, мова застосунку окремо від системи, дозвіл на сповіщення під час роботи, усі PendingIntent незмінні.
- **Стан і запис даних:** `collectAsStateWithLifecycle`, ViewModel із `SavedStateHandle`, запис спершу локально, потім у хмару.
- **Безпека Android:** PIN хешується PBKDF2 (120k ітерацій), R8 увімкнено.
- **PWA:** строгий CSP без `unsafe-inline`, увесь код перевіряється TypeScript у strict-режимі, `:has()`, точкове оновлення DOM.
- **Свідомо не взято, і це правильно:**
  - Navigation 3: 4 маршрути, виграшу нема.
  - M3 Expressive: стабільний лише з material3 1.5.0, який досі RC.
  - Popover і View Transitions: ще не Baseline widely available.
  - CSS nesting: дає лише «модність».

**Де справді відстає:**
- **Версії:** AGP 9.3 → 9.5, Kotlin 2.2 → 2.4, Glance 1.1 → 1.2, Firebase BoM 34 → 35, Firebase JS 12.11 → 13.3 (AND-01, PWA-13).
- **Локальні звички в окремих місцях:** запуск без обробки помилок (AND-03), робота в області корутин composable (AND-04), `runCatching`, що ковтає скасування (AND-10).
- **PWA:** модалки на власному JS замість `<dialog>` і `inert` (PWA-10).
- **Бекенд:** Node 22 знімають з підтримки 2027-10-31, а перехід блокує тригер 1-го покоління (BE-05). Список моделей Gemini застарів (BE-08).

Висновок: проблеми цього репо в **логіці й безпеці** (BE-01, PWA-02..04), а не в «старому стилі». Саме це і варто виправляти першим.
