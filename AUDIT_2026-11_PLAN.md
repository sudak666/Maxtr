# План аудиту Rytm — 2026-11 (від 2.7.5 / vc43)

План для агента, що виконуватиме аудит. Мета — перевірити кожен екран, кожну кнопку і кожне число, а не лише код. Результат пишеться в `AUDIT_2026-11.md` у форматі `AUDIT_2026-10.md`: резюме, baseline, реєстр знахідок з ID (`A1-01` …), серйозність 🔴/🟡/⚪, доказ (файл:рядок, скріншот або вивід команди) і окремий список «не вдалося перевірити».

## 0. Правила виконання

- **Пріоритет — Android** (`./android-app`). PWA — компаньйон для ноутбука (CLAUDE.md «PWA scope»): там перевіряти лише щоденні дії і те, що PWA не псує дані Android.
- **Кожна знахідка підтверджується двічі:** у коді і наживо (QA-збірка на A51 або юніт-тест). «Схоже на баг» без доказу йде в розділ «гіпотези», а не в реєстр.
- **Дані власника.** Робоча версія з Play (`ua.rytm.app`) лише для читання: скріншоти через adb, жодних змін, синхронізацій і видалень без його слова. Усі дії зі змінами — у QA (`ua.rytm.app.qa`, тестовий акаунт), а після аудиту тестові записи прибрати.
- **Конфіденційність.** Суми, імена людей і назви категорій з даних власника не потрапляють у репозиторій (CHANGELOG, аудит, PR). Знахідку з його даних описувати загально: «категорія-переказ сім'ї роздуває середнє».
- **Мерж — лише при зелених перевірках:** спочатку прочитати `gh pr checks`, потім мержити. Двічі сьогодні змерджено з червоним (#706, #719).
- Під час аудиту код не виправляти: тільки реєстр. Виправлення окремими PR після погодження з власником.

## 2. Числа, які бачить користувач (головний пріоритет)

Для кожного числа: звідки воно, чи збігається з іншим місцем, яке показує те саме, і чи зрозуміло, що воно означає.

- [ ] **Загальний баланс** = Σ гаманців з `inCapital` у UAH за курсом; перевірити з депозитом, кредитом, валютним гаманцем, вимкненим «Рахувати в загальному балансі».
- [ ] **«± цього місяця», Дохід, Витрати**: фінансовий місяць з налаштування початку (наприклад, з 10-го), перекази не враховано, гаманці з вимкненою статистикою не враховано.
- [ ] **Чипи гаманців** = баланс у валюті гаманця, з початковим балансом; збігається з «Баланс після операції» у формі і з «залишок» у рядках історії.
- [ ] **Прогноз** (рядок на головній, шторка, віджет): одна функція `CashForecast.forProfile`; сума в шторці сходиться до копійки; «гроші закінчаться» = перший день у мінусі; «Найбільша нестача» з датою; поведінка без історії (< 14 днів), без регулярних платежів, без гаманців, з валютними регулярними.
- [ ] **Звичні витрати:** вікно 60 днів, відкинуто 10 % днів, виключено `rec_` і повтори регулярних (категорія ±10 %). Перевірити, що імпорт виписок і Monobank не дублює витрати (той самий платіж із виписки і зі сповіщення банку).
- [ ] **Бюджети:** витрачено/ліміт, ліміти підкатегорій «Категорія › Підкатегорія», межа фінансового місяця, сповіщення про перевищення (локальне і push) з однаковою логікою.
- [ ] **Цілі:** прогрес = баланс гаманця, 100 % і святкування рівно один раз.
- [ ] **Борги:** залишок = баланс останнього запису (за id) або початкова сума; «Я винен: … · Мені винні: …» по валютах; прогноз погашення; погашений борг не нагадує.
- [ ] **Зміни:** заробіток за місяць, прогноз за графіком автозаповнення, години, вихідні без оплати; зарплата не рахується двічі (зміни + регулярний дохід).
- [ ] **Курси валют:** джерело, дата оновлення, що буває без мережі і без курсу для валюти (41 валюта).
- [ ] **Monobank:** після синхронізації баланс кожного гаманця дорівнює балансу картки (власні гроші без кредитного ліміту); банки стають депозитами; холди; повторна синхронізація не дублює; ліміт API раз на 60 с.
- [ ] **Імпорт виписок** (xlsx monobank, PDF ПУМБ): суми проти підсумків файлу (відома розбіжність жовтня: −1 904,90 / +350, причина невідома); повторний імпорт нічого не дублює; вибір гаманця.
- [ ] **Звіт місяця / PDF** збігається з екраном за той самий місяць.

## 3. Кожен екран і кожна дія (QA на A51, світла і темна тема, шрифт 100 % і 200 %)

Для кожного пункту: відкривається, усі кнопки працюють, «Скасувати» нічого не зберігає, порожній стан зрозумілий, нічого не ховається під системною навігацією чи клавіатурою, текст не обрізається, жодних записів-заготовок «мовчки».

- [ ] **Вхід:** Google, email (реєстрація 8+ символів, вхід старим 6-символьним), скидання пароля, помилки мережі.
- [ ] **Онбординг:** перший запуск, перша витрата, пропуск.
- [ ] **PIN і біометрія:** встановлення, блокування, 5 спроб і пауза, віджет маскує суми.
- [ ] **Фінанси:** форма операції (дохід/витрата/переказ, різні валюти, розділення на категорії, теги, чек, голос), редагування, свайп-видалення, пошук (у т. ч. «кафе жовтень більше 200», `#тег`), фільтри, «Переглянути всі»/«Згорнути», швидкий ввід, підписки-кандидати, розподіл зарплати.
- [ ] **Менеджери:** гаманці, категорії й підкатегорії (перетягування), бюджети, теги, автоправила, регулярні (форма, дата в минулому, поле суми не скаче), цілі, курси, віджети, інструменти.
- [ ] **Зміни:** календар, додати/зняти зміну, типи змін (форма), автозаповнення, експорт ICS.
- [ ] **Борги:** «Я винен»/«Мені винні», валюта, платіж + «Записати й у Фінанси», «Нагадати», термін, прогноз, видалення.
- [ ] **Налаштування:** профілі (створити, перемкнути, поділитися кодом, приєднатися, ролі editor/viewer, вийти), сповіщення (усі перемикачі, час), резервні копії (створити, відновити, `pre_restore`), CSV експорт/імпорт, скидання профілю, видалення акаунта (у тестовому акаунті), мова, тема, початок місяця, Premium-екран при `GATE_ENABLED = false`.
- [ ] **Monobank:** підключити, синхронізувати у фоні (шторку можна закрити), відключити; що з гаманцями після відключення.
- [ ] **Сповіщення банків:** підказка з'являється, швидке збереження за 1 тап, «Скасувати» 10 хв, автозбереження, переказ між двома банками, QA мовчить, поки працює Play-версія.
- [ ] **Віджет:** усі розміри, прогноз, маска, оновлення після операції.
- [ ] **Ярлики, плитка швидких налаштувань, повідомлення-підсумок місяця** відкривають правильну дію.
- [ ] **Офлайн:** додати операцію без мережі → вбити застосунок → увімкнути мережу; конфлікт двох пристроїв; видалення на іншому пристрої не воскресає.
- [ ] **Спільний профіль:** два акаунти (власник + тестовий), viewer не може писати, push учасника.
