# Список покупок — UX-специфікація (Крок 6)

Джерело фактів: [index.html:2076-2107](../index.html), [js/shopping.js](../js/shopping.js), [js/classic-globals.js](../js/classic-globals.js) (I18N.uk).

## Екран
1. **Chip stats**: "Залишилось" (кількість невиконаних), "Куплено" (кількість виконаних).
2. **Форма додавання**: назва товару (обов'язкова, trim, no-op при порожній), кількість (число, дефолт 1 при порожньому/невалідному вводі, `min=1`), кнопка "Додати".
3. **Список**: чекбокс + назва (закреслена + приглушена, якщо куплено) + `×N` праворуч від назви, якщо `qty>1` (не показується для qty=1) + кнопка видалення.
4. **Сортування**: невиконані спершу, виконані — в кінці (stable — порядок додавання зберігається в межах кожної групи).
5. **"Очистити куплені"**: видима лише коли `bought>0`, підтвердження `"Видалити всі куплені товари зі списку?"` перед дією.
6. **Порожній стан**: іконка `cart`, `"Список порожній"`, `"Додай товари перед походом у магазин і відмічай куплене одним тапом."`, CTA `"Додати"` → фокус на полі назви.

## Material3-мапінг
| PWA | Compose |
|---|---|
| chip-stat-row | `Row` з 2 текстовими блоками |
| форма (назва+кількість+кнопка) | `OutlinedTextField` × 2 + `Button` |
| рядок товару | `Checkbox` + `Text` (strikethrough via `TextDecoration.LineThrough`) + qty label + `IconButton` |
| "Очистити куплені" | `TextButton`, умовна видимість |
| підтвердження | `AlertDialog` |

## Room

Нова таблиця → `RytmDatabase` version 2 з `fallbackToDestructiveMigration()` (пре-лонч, без реальних користувачів — той самий принцип, що й PWA-конвенція "не захищати міграцією дані, яких ще нема").
